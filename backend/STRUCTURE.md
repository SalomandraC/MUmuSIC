## 2. ОПРЕДЕЛЕНИЯ

API (Application Programming Interface) – интерфейс программирования приложений, набор методов и правил, позволяющий различным программным компонентам взаимодействовать друг с другом.

Access токен – JWT токен доступа с ограниченным временем жизни, используемый для аутентификации пользователя при выполнении запросов к защищенным ресурсам API.

Аутентификация – процесс проверки подлинности пользователя, подтверждающий его личность на основе учетных данных (email, пароль).

Авторизация – процесс определения прав доступа пользователя к определенным ресурсам или операциям в системе.

Backend (серверная часть) – компонент программного обеспечения, работающий на сервере и отвечающий за выполнение бизнес-логики, хранение и обработку данных, аутентификацию пользователей и обеспечение взаимодействия с клиентской частью приложения.

bcrypt – алгоритм хеширования паролей, используемый для безопасного хранения паролей в базе данных с применением адаптивной функции хеширования на основе алгоритма Blowfish.

BearerAuth – схема аутентификации HTTP, при которой токен доступа передается в заголовке Authorization в формате "Bearer <token>".

CORS (Cross-Origin Resource Sharing) – механизм безопасности браузера, позволяющий веб-страницам делать запросы к серверу с другого домена, порта или протокола, контролируемый специальными HTTP-заголовками.

Эндпоинт (endpoint) – конкретный URL-адрес в API, обрабатывающий определенный тип запроса (GET, POST, DELETE и т.д.) и возвращающий соответствующий ответ.

Express – минималистичный и гибкий веб-фреймворк для Node.js, предоставляющий набор функций для создания веб-приложений и API.

Гостевая сессия – временная сессия для неавторизованных пользователей, позволяющая ограниченный доступ к функциональности приложения без регистрации.

Hash (хеш) – результат преобразования данных (например, пароля) с помощью криптографической хеш-функции, представляющий собой фиксированную строку символов, из которой невозможно восстановить исходные данные.

Health check – эндпоинт для проверки работоспособности сервера или системы, используемый для мониторинга состояния приложения.

HTTP Range-запрос – HTTP-запрос с заголовком Range, позволяющий запрашивать определенную часть файла, что используется для потоковой передачи медиа-контента и поддержки воспроизведения с произвольной позиции.

HTTP-ошибка – стандартизированный код состояния HTTP, указывающий на результат обработки запроса (например, 404 – ресурс не найден, 500 – внутренняя ошибка сервера).

JSDoc (JavaScript Documentation) – стандарт документации для JavaScript-кода, использующий специальные комментарии для описания функций, параметров, возвращаемых значений и типов.

JSON (JavaScript Object Notation) – текстовый формат обмена данными, основанный на синтаксисе JavaScript, широко используемый для передачи структурированных данных между клиентом и сервером.

JWT (JSON Web Token) – открытый стандарт для создания токенов доступа, представляющий собой компактный и самодостаточный способ безопасной передачи информации между сторонами в виде JSON-объекта.

Middleware (промежуточное программное обеспечение) – функция или набор функций, выполняемых между получением запроса и отправкой ответа, используемые для обработки запросов, аутентификации, логирования, обработки ошибок и других задач.

MIME-тип (Multipurpose Internet Mail Extensions) – стандарт для указания типа содержимого файла, передаваемого через интернет (например, audio/mpeg для MP3-файлов, application/json для JSON-данных).

Morgan – middleware для Node.js, обеспечивающий логирование HTTP-запросов в различных форматах для мониторинга и отладки.

NFC (Near Field Communication) – технология беспроводной связи малого радиуса действия, используемая для обмена данными между устройствами на расстоянии до 10 см.

Node.js – серверная платформа на основе JavaScript-движка V8, позволяющая выполнять JavaScript-код вне браузера и создавать масштабируемые сетевые приложения.

OpenAPI (Open API Specification) – спецификация для описания REST API, позволяющая описать структуру, параметры, ответы и другую информацию об API в машиночитаемом формате.

Path traversal атака – тип атаки, при котором злоумышленник пытается получить доступ к файлам и директориям, находящимся вне предполагаемой корневой директории веб-приложения, путем манипуляции путями к файлам.

PostgreSQL – объектно-реляционная система управления базами данных с открытым исходным кодом, поддерживающая расширенные возможности работы с данными.

Потоковая передача (streaming) – способ передачи данных, при котором информация отправляется непрерывным потоком и может обрабатываться по мере поступления, без необходимости загрузки всего файла целиком.

REST (Representational State Transfer) – архитектурный стиль проектирования веб-сервисов, использующий стандартные HTTP-методы (GET, POST, PUT, DELETE) для взаимодействия с ресурсами через URL.

REST API – веб-сервис, реализующий архитектурный стиль REST и предоставляющий доступ к ресурсам через стандартизированные HTTP-методы и форматы данных.

SQL (Structured Query Language) – декларативный язык программирования, используемый для управления данными в реляционных базах данных, включая создание, чтение, обновление и удаление записей.

СУБД (Система управления базами данных) – программное обеспечение для создания, управления и обслуживания баз данных, обеспечивающее целостность, безопасность и эффективность работы с данными.

Refresh токен – JWT токен обновления с длительным временем жизни, используемый для получения нового access токена без повторной аутентификации пользователя.

Репозиторий (repository) – слой абстракции, инкапсулирующий логику доступа к данным и обеспечивающий централизованное управление запросами к базе данных.

Соль (salt) в криптографии – случайные данные, добавляемые к паролю перед хешированием для повышения безопасности и предотвращения атак с использованием радужных таблиц.

Санитизация – процесс очистки и валидации пользовательских данных для предотвращения уязвимостей безопасности, таких как SQL-инъекции, XSS-атаки и path traversal.

Сервис (service) – компонент приложения, содержащий бизнес-логику и переиспользуемую функциональность, не зависящую от конкретной реализации интерфейса пользователя.

Swagger – набор инструментов для проектирования, документирования и тестирования REST API на основе спецификации OpenAPI.

Swagger UI – интерактивный интерфейс для визуализации и тестирования API, генерируемый на основе OpenAPI спецификации.

TypeScript – типизированный надмножество JavaScript, компилируемое в обычный JavaScript, обеспечивающее статическую типизацию и улучшенную поддержку разработки.

TTL (Time To Live) – время жизни токена или сессии, определяющее период, в течение которого они остаются действительными.

UUID (Universally Unique Identifier) – стандартизированный формат 128-битного идентификатора, гарантирующий уникальность значения в глобальном масштабе.

URL (Uniform Resource Locator) – адрес ресурса в интернете, определяющий протокол, доменное имя, путь к ресурсу и опциональные параметры.

Валидация – процесс проверки данных на соответствие определенным правилам и ограничениям перед их обработкой или сохранением.

Верификация токена – процесс проверки подлинности и действительности JWT токена, включая проверку подписи, срока действия и целостности данных.

Версионирование токенов – механизм управления токенами, позволяющий инвалидировать все существующие токены пользователя при изменении учетных данных или обнаружении компрометации.

Генерирование токена – процесс создания JWT токена на основе данных пользователя с добавлением подписи и метаданных (время создания, срок действия).

Время жизни токена (TTL) – период времени, в течение которого токен остается действительным и может использоваться для аутентификации.

Контроллер (controller) – компонент приложения, обрабатывающий HTTP-запросы, вызывающий соответствующие сервисы и формирующий ответы клиенту.

Маршрут (route) – определение соответствия между URL-адресом, HTTP-методом и обработчиком запроса в веб-приложении.

Переменные окружения – переменные конфигурации, хранящиеся в операционной системе или файле .env, используемые для настройки приложения без изменения кода.

Поток (stream) – абстракция в Node.js для работы с данными, которые могут обрабатываться по частям без загрузки всего объема в память.

Хеширование паролей – процесс преобразования пароля в хеш с использованием криптографической функции, обеспечивающий безопасное хранение паролей без возможности их восстановления.

Zod – библиотека для валидации и парсинга данных в TypeScript, использующая декларативные схемы для определения структуры и ограничений данных.


## 3.1. Модуль аутентификации и управления пользователями (auth)

Данный модуль реализует функционал аутентификации и управления пользователями, включая регистрацию новых пользователей, вход в систему через email и пароль, управление JWT токенами (access и refresh), создание и валидацию гостевых сессий, смену пароля авторизованных пользователей, а также восстановление пароля через токены сброса. Модуль обеспечивает валидацию вводимых данных с использованием Zod-схем, хеширование паролей с помощью bcrypt, управление ролями пользователей и интеграцию с базой данных для хранения пользовательских данных и сессий.

## 3.2. Модуль работы с гостевыми треками (guest)

Данный модуль реализует функционал для работы с треками, доступными для гостевых пользователей. Модуль обеспечивает получение списка активных гостевых треков из базы данных, потоковую передачу аудиофайлов с поддержкой HTTP Range-запросов для поддержки воспроизведения с произвольной позиции, поиск и потоковую передачу треков по названию, а также специальную функциональность для работы с треками из папки NFC с расширенной логикой поиска файлов по названию (поддержка совпадений с различными расширениями, игнорирование префиксов, поиск по частичным совпадениям). Модуль интегрирован с файловой системой для доступа к аудиофайлам и обеспечивает определение MIME-типов файлов для корректной передачи контента.

## 3.3. Модуль работы с файлами пользователей (files)

Данный модуль реализует функционал для управления файлами зарегистрированных пользователей, включая загрузку аудиофайлов (mp3, wav) в персональные директории пользователей, получение списка файлов пользователя, удаление конкретных файлов, а также прямой доступ к файлам через URL вида `/:accountId/:fileName`. Модуль обеспечивает безопасное хранение файлов с изоляцией по пользователям, санитизацию имен файлов для предотвращения path traversal атак, валидацию типов загружаемых файлов и автоматическое создание директорий для пользователей. Файлы хранятся в структурированной файловой системе с организацией по идентификаторам аккаунтов.

## 3.4. Модуль отладки и диагностики (debug)

Данный модуль реализует вспомогательные эндпоинты для диагностики и отладки системы, включая проверку подключения к базе данных через получение списка всех треков из таблицы tracks. Модуль предназначен для разработки и тестирования, позволяя быстро проверять состояние базы данных и корректность выполнения запросов без необходимости использования дополнительных инструментов.

## 3.5. Конфигурационный модуль (config)

Данный модуль реализует централизованное управление конфигурацией приложения, включая загрузку и валидацию переменных окружения с использованием Zod-схем, настройку подключения к базе данных PostgreSQL через библиотеку postgres, конфигурацию JWT токенов (секреты, время жизни access и refresh токенов), настройку параметров сессий пользователей, конфигурацию времени жизни гостевых сессий, определение пути к корневой директории хранилища файлов, а также настройки для различных окружений (development, test, production). Модуль обеспечивает типобезопасность конфигурации и централизованное управление всеми настройками приложения.

## 3.6. Модуль промежуточного программного обеспечения (middleware)

Данный модуль реализует промежуточные обработчики запросов, включая обработку асинхронных функций с автоматической обработкой ошибок через asyncHandler, проверку аутентификации пользователей через JWT токены в заголовке Authorization (authGuard), проверку прав доступа на основе ролей пользователей (roleGuard), централизованную обработку ошибок с поддержкой Zod-валидации и HTTP-ошибок, а также обработку 404 ошибок для несуществующих маршрутов. Модуль обеспечивает безопасность API, валидацию запросов и единообразную обработку ошибок во всем приложении.

## 3.7. Модуль сервисов (services)

Данный модуль реализует переиспользуемые сервисы для работы с различными компонентами системы, включая генерацию и верификацию JWT токенов различных типов (access, refresh, password reset) через библиотеку jsonwebtoken, хеширование паролей с использованием bcrypt с настраиваемым количеством раундов соли, сравнение введенных паролей с хешами в базе данных, а также управление жизненным циклом токенов с учетом версионирования и времени жизни. Модуль обеспечивает криптографическую безопасность и переиспользуемую логику для работы с аутентификацией.

## 3.8. Модуль утилит (utils)

Данный модуль реализует вспомогательные утилиты и классы для работы приложения, включая класс HttpError для создания структурированных HTTP-ошибок с кодом статуса и сообщением, функцию createHttpError для удобного создания экземпляров ошибок, а также другие утилитарные функции, используемые в различных модулях приложения. Модуль обеспечивает единообразную обработку ошибок и переиспользуемые утилиты.

## 3.9. Модуль документации API (swagger)

Данный модуль реализует автоматическую генерацию и обслуживание документации API с использованием Swagger/OpenAPI спецификации, включая интеграцию swagger-ui-express для интерактивной документации, описание всех эндпоинтов API с параметрами запросов и ответов, определение схем данных (User, Track, GuestTrack, AuthTokens и др.), описание систем безопасности (bearerAuth для JWT токенов), а также автоматическое извлечение документации из JSDoc комментариев в коде. Модуль обеспечивает доступ к документации API по адресу `/api-docs` и упрощает интеграцию с API для разработчиков.

## 3.10. Основной модуль приложения (index)

Данный модуль реализует инициализацию и запуск Express-сервера, включая настройку CORS с поддержкой различных источников запросов, конфигурацию логирования запросов через morgan, настройку парсинга JSON и URL-encoded данных, регистрацию всех маршрутов приложения (auth, guest-tracks, files, debug), настройку статической раздачи файлов из директории storage, интеграцию Swagger UI для документации API, обработку health check запросов, а также запуск HTTP-сервера на указанном порту. Модуль является точкой входа в приложение и координирует работу всех остальных модулей.
