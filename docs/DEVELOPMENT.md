# Работа с проектом

## Голосовой запуск локального трека на Android

На компьютере с Ollama выполните `ollama pull hf.co/taobao-mnn/MNN-Pocket-0.3B-GGUF:Q4_1`.
Для подключённого Android-устройства выполните `adb reverse tcp:11434 tcp:11434`.
Клиент по умолчанию использует этот туннель. Другой адрес задаётся при запуске
через `flutter run --dart-define=POCKET_URL=http://HOST:PORT`.
Модель работает на компьютере и получает только распознанную фразу.
Телефону требуется системный обработчик распознавания речи для английского языка.
Во «Внутреннем хранилище» импортируйте файл с названием «404»,
нажмите микрофон и скажите «Play me track four hundred four».
Плеер запускает единственное совпадение среди показанных локальных записей.

Команды ниже рассчитаны на PowerShell. Переходы `Set-Location` в начале каждого сценария указаны относительно корня репозитория. Для разных компонентов удобно открыть отдельные терминалы.

## Требования

- Flutter с Dart, совместимым с `pubspec.yaml` (`>=3.0.0 <4.0.0`) и зафиксированными зависимостями `pubspec.lock`; Android SDK и устройство/эмулятор для Android.
- Docker с Compose для контейнерного сервера, либо JDK 21, Maven 3.9 и PostgreSQL для локального Java API.
- Node.js и npm нужны только для предыдущего `backend/`.

Проверка окружения: `flutter doctor`, `flutter devices`, `java -version`, `mvn -version`, `docker compose version`. Диапазон Dart в манифесте не гарантирует совместимость любой старой версии Flutter со всеми зависимостями. Точная версия Flutter в корневой документации проекта не закреплена.

## Java API через Docker

```powershell
Set-Location backend-java
if (!(Test-Path .env)) { Copy-Item .env.example .env }
```

Заполните в `.env` два разных JWT-секрета длиной не менее 32 символов. При переходе с существующего Node API сохраните его секреты для совместимости выданных токенов. Compose сам задаёт адрес своей БД и путь `/data/storage`; остальные параметры смотрите в `docker-compose.yml`.

```powershell
docker compose up -d --build
docker compose ps
docker compose logs --tail 100 api
Invoke-RestMethod http://localhost:5050/health
Invoke-RestMethod http://localhost:5050/ready
```

Swagger: `http://localhost:5050/api-docs`. PostgreSQL доступен с хоста на `localhost:5433`, база и пользователь — `mumusic`. Пароль задаёт `POSTGRES_PASSWORD`, резервное значение для локального стенда — `mumusic`.

Перед сменой реализации остановите предыдущий стенд командой `docker compose down` из его каталога. Обычный `down` сохраняет том БД. Опция `-v` удаляет данные тома и не нужна для повседневной работы. Java и Node используют один Compose-проект `mumusic` и общее аудиохранилище.

## Java API без контейнера приложения

Из `backend-java/` подготовьте `.env` из примера, если его ещё нет. Для PostgreSQL, опубликованного Compose на хосте, настройте:

```dotenv
DATABASE_URL=postgres://mumusic:YOUR_LOCAL_PASSWORD@localhost:5433/mumusic
DATABASE_SSL=disable
```

Также заполните JWT-секреты. Для другой БД укажите её фактический адрес. Если нужен только контейнер PostgreSQL, из `backend-java/` выполните `docker compose up -d postgres`; при уже работающем контейнере API сначала остановите его (`docker compose stop api`), чтобы освободить порт 5050.

```powershell
mvn spring-boot:run
```

Flyway применяет миграции при старте. Запускать приложение нужно из `backend-java/`, чтобы относительные пути `.env` и хранилища разрешались ожидаемым образом.

## Flutter

```powershell
Set-Location tier-maker/tiermaker
if (!(Test-Path .env)) { Copy-Item .env.example .env }
flutter pub get
flutter devices
flutter run -d <device-id>
```

Перед запуском замените `API_BASE_URL` в `.env` на адрес вашего API, без завершающего `/`. `<device-id>` — идентификатор из `flutter devices`.

| Устройство | Значение `API_BASE_URL` для локального API |
|---|---|
| Приложение на том же компьютере | `http://localhost:5050` |
| Стандартный Android Emulator | `http://10.0.2.2:5050` |
| Физический телефон в той же сети | `http://<LAN-IP-компьютера>:5050` |

Адрес в существующем `.env.example` привязан к конкретной локальной сети. На телефоне `localhost` означает сам телефон. Проверьте доступность порта 5050 с устройства и сетевые правила компьютера.

Сохранённый в Hive URL имеет приоритет над `.env` в API-клиентах; изменение `.env` не переопределяет уже сохранённую настройку. Учитывайте также кэши URL в клиентах. После изменения конфигурации полностью перезапустите приложение; при сохранённом старом URL обновите/сбросьте его через соответствующие методы клиента (`GuestTracksApi.setBaseUrl/resetBaseUrl`) или диагностический код.

`.env` включён в Flutter assets: он нужен при сборке и не должен содержать серверные секреты. Наличие папок web/desktop не подтверждает работоспособность всех функций на этих платформах: код использует `dart:io`, аудио, файловые и NFC-плагины. NFC проверяется на поддерживаемом физическом устройстве.

## Проверки и сборка

| Компонент, рабочий каталог | Проверки | Сборка |
|---|---|---|
| Flutter, `tier-maker/tiermaker` | `flutter analyze`, `flutter test` | `flutter build apk --debug` |
| Java, `backend-java` | `mvn test` | `mvn package` (также выполняет тесты) |
| Node, `backend` | `npm ci`, затем `npm test -- --runInBand` | `npm run build` |

Java JAR: `backend-java/target/mumusic-api.jar`. Flutter APK: `tier-maker/tiermaker/build/app/outputs/flutter-apk/app-debug.apk`. Java-тесты находятся в `src/test/java`, Flutter-тесты — в `test/`, Node-тесты — в `server/**/__tests__/`.

Для запуска предыдущего API из `backend/`: подготовьте `.env` по его примеру, выполните `npm ci`, `npm run migrate`, `npm run dev`. Команда миграции изменяет выбранную БД; проверьте `DATABASE_URL`. В `server/` обычные команды запуска отключены намеренно.

## Ручная проверка после функциональных изменений

Проверьте затронутый сценарий: гостевой каталог и плеер; регистрацию/вход и восстановление сессии; поиск и превью iTunes; загрузку и воспроизведение своего файла; плейлист и синхронизацию; локальное воспроизведение без сети. Для изменений доступа проверьте, что второй пользователь не получает личные файлы первого. `/health` проверяет процесс, `/ready` — готовность БД и хранилища.

## Типовые причины проблем

- Сервер не стартует: пустые/одинаковые/короткие JWT-секреты, недоступная БД, занятый порт 5050.
- Каталог пуст при наличии MP3: файлы на диске и записи `guest_tracks` — разные части данных; миграции создают схему, но не импортируют каталог.
- Аудио не открывается: проверьте `STORAGE_ROOT`, `file_path`, наличие файла и срок действия подписанного URL.
- Flutter обращается к старому адресу: проверьте `.env`, сохранённый в Hive адрес и кэш клиента.
- `mvn` не найден: Maven отсутствует в PATH; Maven Wrapper в проекте не обнаружен. Используйте установленный Maven либо контейнерную сборку.
