# 4. ПРИНЦИП РАБОТЫ ПРОГРАММНОГО ОБЕСПЕЧЕНИЯ

## 4.1. Мобильное приложение

Мобильное приложение MuMuSIC разработано с использованием кроссплатформенного фреймворка Flutter, что обеспечивает единообразный пользовательский интерфейс и функциональность на различных платформах (Android, iOS). Приложение реализует современный и интуитивно понятный пользовательский интерфейс, соответствующий принципам Material Design, что обеспечивает комфортное взаимодействие пользователя с системой. Интерфейс приложения включает адаптивные компоненты, которые автоматически подстраиваются под размер экрана устройства и ориентацию, обеспечивая оптимальное отображение контента на различных типах устройств. Визуальное оформление приложения поддерживает светлую и тёмную темы оформления, которые могут быть переключены пользователем в настройках, что обеспечивает комфортное использование приложения в различных условиях освещения. Пользовательский интерфейс реализует плавные анимации переходов между экранами, визуальную обратную связь при взаимодействии с элементами управления и индикаторы загрузки для операций, требующих времени на выполнение. Функциональность интерфейса включает навигационное меню с логически организованными разделами, поисковые поля с автоматическим debouncing для оптимизации запросов, списки треков с обложками и метаданными, полнофункциональный аудиоплеер с элементами управления воспроизведением и прогресс-баром, а также диалоговые окна для подтверждения действий и отображения информации пользователю.

## 4.2. Инициализация приложения

При запуске приложения выполняется последовательная инициализация компонентов системы. На этапе инициализации происходит инициализация Flutter-движка через вызов `WidgetsFlutterBinding.ensureInitialized()`, что обеспечивает готовность платформы к работе с виджетами. Затем выполняется инициализация локальной базы данных Hive посредством вызова `AppDatabase.init()`, в процессе которой создаётся и открывается хранилище для сохранения состояния приложения, настроек пользователя и параметров подключения к внешним сервисам. Параллельно выполняется загрузка базового URL для API гостевых треков из локального хранилища или установка значения по умолчанию. После завершения инициализации хранилища создаётся экземпляр `AppModel`, который загружает сохранённое состояние приложения (тема оформления, язык интерфейса, статус авторизации) и уведомляет подписчиков об изменении состояния через механизм `ChangeNotifier`.

## 4.3. Аутентификация и определение режима работы

Модуль аутентификации определяет режим работы приложения на основе данных, загруженных из локального хранилища. При первом запуске приложения или при отсутствии сохранённых данных о пользователе система автоматически устанавливает гостевой режим работы. Пользователь может выполнить вход в систему, введя email и пароль, или зарегистрироваться, указав дополнительно никнейм. В процессе регистрации выполняется валидация введённых данных: проверка формата email, минимальной длины пароля и наличия обязательных полей. После успешной аутентификации или выбора гостевого режима состояние пользователя сохраняется в локальной базе данных Hive, а информация о режиме работы передаётся в глобальную модель состояния приложения через `AppModel.setGuestMode()` или `AppModel.setUserInfo()`. Система маршрутизации на основе статуса пользователя определяет доступные экраны и ограничивает доступ к функциям, требующим авторизации.

## 4.4. Навигация и отображение главного экрана

Система навигации реализована на основе библиотеки go_router, которая обеспечивает декларативное определение маршрутов и управление переходами между экранами. При инициализации приложения создаётся экземпляр `GoRouter` с конфигурацией маршрутов, включающей правила перенаправления на основе статуса авторизации пользователя. Главный экран приложения отображает навигационное меню с элементами, доступность которых зависит от режима работы пользователя. Для гостевых пользователей доступны базовые функции (Сеть, NFC, Настройки), в то время как авторизованным пользователям предоставляется расширенный набор функций. При выборе пункта меню система навигации выполняет переход на соответствующий экран через механизм `context.push()` или `context.go()`, при этом происходит проверка прав доступа и применение правил маршрутизации, определённых в конфигурации роутера.

## 4.5. Поиск треков в сети iTunes

Модуль поиска треков реализует функционал поиска музыкальных композиций через публичный API сервиса iTunes. При вводе текста в поле поиска активируется механизм debouncing, который откладывает выполнение запроса на одну секунду после последнего ввода символа, что позволяет уменьшить количество запросов к API и оптимизировать использование сетевых ресурсов. По иступлении таймаута debouncing формируется HTTP-запрос к эндпоинту iTunes API с параметрами поискового запроса, типа медиа (music) и ограничения количества результатов. Полученный ответ в формате JSON проходит десериализацию, в процессе которой извлекаются данные о треках (название, исполнитель, длительность, URL обложки, URL превью) и формируется список объектов `NetworkTrack`. Результаты поиска отображаются в виде списка с элементами, содержащими обложку трека, название, исполнителя и длительность, а также индикатор наличия превью для предпрослушивания.

## 4.6. Воспроизведение треков

Модуль воспроизведения аудио реализован на основе библиотеки just_audio, которая обеспечивает кроссплатформенное воспроизведение аудиофайлов из различных источников. При выборе трека для воспроизведения система извлекает URL превью из объекта трека и создаёт экземпляр `AudioSource.uri` с указанным URL. Аудиоплеер выполняет загрузку аудиофайла по сети, в процессе которой происходит буферизация данных для обеспечения плавного воспроизведения. После успешной загрузки и подготовки источника система начинает воспроизведение трека и подписывается на потоки событий плеера для отслеживания позиции воспроизведения, длительности трека и состояния воспроизведения. Пользовательский интерфейс отображает элементы управления воспроизведением (пауза, остановка, изменение скорости), а также прогресс-бар с возможностью перемотки трека. При воспроизведении трека из сети iTunes используется previewUrl, который предоставляет ограниченный по времени фрагмент композиции, в то время как для гостевых треков используется полный потоковый URL с сервера.

## 4.7. Скачивание треков на устройство

Модуль скачивания треков обеспечивает сохранение аудиофайлов на локальное хранилище устройства. При инициации процесса скачивания система проверяет наличие необходимых разрешений для доступа к хранилищу устройства: для Android версий до 13 используется разрешение `WRITE_EXTERNAL_STORAGE`, для более новых версий – `READ_MEDIA_AUDIO`. После получения разрешений система определяет директорию для сохранения файлов: для Android используется внешнее хранилище (`/storage/emulated/0/Download/MuMuSIC`), для iOS – директория Documents приложения. Формируется имя файла на основе названия трека и исполнителя с очисткой недопустимых символов. Выполняется HTTP-запрос для загрузки аудиофайла по URL превью или потоковому URL, полученные данные сохраняются в файл на устройстве. В процессе скачивания отображается индикатор загрузки, а после завершения пользователю предоставляется уведомление с путём к сохранённому файлу.

## 4.8. Работа с гостевыми треками

Модуль работы с гостевыми треками обеспечивает взаимодействие с внешним сервером для получения списка треков, доступных гостевому пользователю. При открытии экрана гостевых треков выполняется HTTP-запрос к эндпоинту сервера `/guest-tracks` с использованием базового URL, загруженного из настроек приложения или установленного по умолчанию. Полученный ответ в формате JSON содержит массив объектов треков с полной информацией о композициях, включая идентификатор, название, исполнителя, длительность, путь к файлу и URL для потокового воспроизведения. Данные проходят десериализацию и преобразуются в список объектов `GuestTrack`, которые отображаются в пользовательском интерфейсе. При выборе трека для воспроизведения система формирует потоковый URL на основе идентификатора трека или использует предустановленный streamUrl из объекта трека, после чего инициирует процесс воспроизведения через аудиоплеер.

## 4.9. Работа с NFC-метками

Модуль работы с NFC обеспечивает чтение данных с NFC-меток и интеграцию полученной информации с системой воспроизведения треков. При активации функции чтения NFC система проверяет доступность NFC-технологии на устройстве и запрашивает необходимые разрешения для работы с NFC. После поднесения устройства к NFC-метке система инициирует процесс чтения данных через библиотеку flutter_nfc_kit, которая обеспечивает низкоуровневое взаимодействие с NFC-контроллером устройства. Прочитанные данные обрабатываются для извлечения информации о треке (название, исполнитель), которая используется для поиска соответствующего трека в базе данных или для формирования запроса к API сервера. Найденный трек автоматически добавляется в очередь воспроизведения или начинает воспроизведение немедленно, в зависимости от настроек приложения.

## 4.10. Управление настройками и сохранение состояния

Модуль управления настройками обеспечивает изменение параметров приложения и сохранение состояния для последующих сессий. При изменении темы оформления (светлая/тёмная) система обновляет глобальное состояние приложения через `AppModel.setTheme()`, что приводит к изменению цветовой схемы всех экранов приложения через механизм `ListenableBuilder`, который реагирует на изменения в `ChangeNotifier`. Новое состояние темы сохраняется в локальную базу данных Hive в формате строки состояния приложения, что обеспечивает восстановление выбранной темы при следующем запуске приложения. Аналогичным образом сохраняются настройки подключения к API серверу, язык интерфейса и другие параметры конфигурации. При изменении базового URL для API гостевых треков выполняется валидация формата URL и сохранение в локальное хранилище, после чего обновляется кэшированное значение в модуле работы с API.

## 4.11. Управление сессиями и выход из аккаунта

При выходе пользователя из аккаунта или завершении гостевой сессии система выполняет очистку данных сессии и сброс состояния авторизации. Процесс выхода инициируется через диалог подтверждения, после чего вызывается метод `AppModel.setGuestMode(true)`, который устанавливает статус гостевого пользователя, очищает данные о пользователе (email, никнейм) из локального хранилища и уведомляет подписчиков об изменении состояния. Система навигации автоматически перенаправляет пользователя на экран аутентификации на основе правил маршрутизации, определённых в конфигурации роутера. При этом сохраняются настройки приложения (тема, язык), которые не зависят от статуса авторизации, что обеспечивает комфортный пользовательский опыт при повторном входе в систему.
