# ОПРЕДЕЛЕНИЯ

**API (Application Programming Interface)** – интерфейс программирования приложений, набор методов и правил, позволяющий различным программным компонентам взаимодействовать друг с другом. В контексте приложения используется для взаимодействия с внешними сервисами, такими как iTunes API для поиска музыкальных треков.

**Аутентификация** – процесс проверки подлинности пользователя, подтверждение его личности через ввод учетных данных (email, пароль) или использование альтернативных методов входа (гостевой режим).

**Авторизация** – процесс определения прав доступа пользователя к различным функциям и ресурсам приложения на основе его статуса (гостевой пользователь или авторизованный пользователь).

**Аудиоплеер** – компонент приложения, обеспечивающий воспроизведение аудиофайлов, включающий функции управления воспроизведением (воспроизведение, пауза, остановка), изменение скорости воспроизведения и контроль позиции воспроизведения.

**Backend (серверная часть)** – компонент программного обеспечения, работающий на сервере и отвечающий за выполнение бизнес-логики, хранение и обработку данных, аутентификацию пользователей и обеспечение взаимодействия с клиентской частью приложения.

**ChangeNotifier** – класс из библиотеки Flutter, реализующий паттерн Observer, который позволяет уведомлять подписчиков об изменениях состояния объекта.

**Debouncing** – техника программирования, при которой выполнение функции откладывается до тех пор, пока не пройдет определенный период времени после последнего вызова, что позволяет уменьшить количество запросов к API при вводе текста в поле поиска.

**Dart** – объектно-ориентированный язык программирования, разработанный компанией Google, используемый для создания приложений на платформе Flutter.

**Domain Layer (слой домена)** – слой архитектуры приложения, содержащий бизнес-логику, модели данных и правила предметной области, независимые от пользовательского интерфейса и внешних зависимостей.

**Flutter** – кроссплатформенный фреймворк от Google для создания мобильных, веб- и настольных приложений с использованием языка программирования Dart.

**Frontend (клиентская часть)** – часть программного обеспечения, которая работает на устройстве пользователя и включает пользовательский интерфейс, обеспечивающий взаимодействие с пользователем и отображение данных, полученных от серверной части.

**go_router** – библиотека для управления навигацией в Flutter-приложениях, предоставляющая декларативный способ определения маршрутов и переходов между экранами.

**Гостевой режим** – режим работы приложения, при котором пользователь может использовать базовый функционал без регистрации и авторизации, с ограниченным доступом к некоторым функциям.

**Hive** – легковесная NoSQL база данных для Flutter и Dart, используемая для локального хранения данных на устройстве пользователя.

**InheritedWidget** – базовый виджет Flutter, который позволяет передавать данные вниз по дереву виджетов без явной передачи через конструкторы, используется для реализации паттерна Provider.

**iTunes API** – публичный API сервиса iTunes, предоставляющий доступ к каталогу музыки, фильмов, приложений и другого контента, используемый в приложении для поиска музыкальных треков.

**Маршрутизация** – процесс определения и управления путями навигации между различными экранами приложения, включая определение доступных маршрутов и правил перехода между ними.

**Material Design** – система дизайна, разработанная Google, определяющая принципы визуального оформления, типографики, цветовых схем и компонентов пользовательского интерфейса.

**MVP (Minimum Viable Product)** – минимально жизнеспособный продукт, содержащий только основные функции, достаточные для удовлетворения первичных потребностей пользователей и проверки гипотез о полезности продукта.

**MySQL** – реляционная система управления базами данных с открытым исходным кодом, используемая для хранения и управления структурированными данными.

**NFC (Near Field Communication)** – технология беспроводной связи ближнего радиуса действия, позволяющая обмениваться данными между устройствами на расстоянии до 10 см, используемая в приложении для чтения информации с NFC-меток.

**Навигация** – процесс перехода пользователя между различными экранами и разделами приложения, реализуемый через систему маршрутизации.

**PreviewUrl** – URL-адрес, предоставляющий доступ к предварительному прослушиванию музыкального трека, обычно ограниченный по времени воспроизведения (обычно 30 секунд).

**Presentation Layer (слой представления)** – слой архитектуры приложения, отвечающий за отображение данных пользователю, обработку пользовательского ввода и взаимодействие с пользовательским интерфейсом.

**Provider** – паттерн управления состоянием в Flutter, реализованный через InheritedWidget, который позволяет эффективно передавать и обновлять состояние приложения между компонентами.

**Repository (репозиторий)** – паттерн проектирования, абстрагирующий доступ к данным и предоставляющий единый интерфейс для работы с различными источниками данных (локальная база данных, сетевые API).

**Сессия пользователя** – период активного использования приложения пользователем, начинающийся с момента входа (авторизации или гостевого режима) и заканчивающийся при выходе из приложения или смене пользователя.

**State Management (управление состоянием)** – подход к организации и управлению состоянием приложения, обеспечивающий согласованность данных между различными компонентами и эффективное обновление пользовательского интерфейса при изменении состояния.

**Темизация** – процесс настройки визуального оформления приложения, включающий определение цветовых схем, стилей компонентов, типографики и других визуальных параметров для обеспечения единообразного внешнего вида.

**Типографика** – искусство и техника оформления текста, включающая выбор шрифтов, размеров, межстрочных интервалов и других параметров для обеспечения читаемости и визуальной привлекательности текста.

**UseCase (сценарий использования)** – паттерн проектирования, инкапсулирующий бизнес-логику для выполнения конкретной задачи или операции, обеспечивающий разделение ответственности и переиспользуемость кода.

**Валидация** – процесс проверки корректности введенных пользователем данных согласно установленным правилам и требованиям, включающий проверку формата, наличия обязательных полей и соответствия ограничениям.

**Виджет** – базовый строительный блок пользовательского интерфейса в Flutter, представляющий собой неизменяемый объект, описывающий часть пользовательского интерфейса.
